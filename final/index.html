01   Abstract

Summary

This project combines rendering techniques with mesh generation to recreate the visual effects of snow accumulation within an arbitrary scene. To approximate the visual effects of snow, we implemented a custom SnowBSDF that blends a Lambertian diffuse base with Beckmann importance sampling, sampled via triplanar texture mapping to work on UV-less SDF-generated meshes. To model the buildup of snow, we used signed distance fields with a Surface Nets algorithm, placing a realistic layer of textured snow on any mesh scene.

Our initial goal was to implement the full Kemppinen et al. glint algorithm, which required differential rays, a custom DiffRay type, and a 2D Jacobian for UV footprint computation. While the differential ray infrastructure was completed, the full glint algorithm proved too complex to port from its GLSL shader origin within the project timeline. The final snow material instead achieves its sparkle through Beckmann NDF importance sampling layered on top of a diffuse texture, producing a convincing snow appearance without the full glint pipeline.

02   Technical Approach

How We Built It

Microfacet BSDF Foundation — Charlie Herbert

The HW3 renderer only supports Lambertian BSDFs, which is insufficient for snow's visual properties. We extended it with a full microfacet BSDF based on Walter et al., implementing the Beckmann normal distribution function, a dielectric Fresnel term, and the Smith-Beckmann geometric attenuation term. This formed the foundation that all later snow material work was built on top of.

Glint Model Attempt — Kemppinen et al. — Charlie Herbert · Allena Ogilvie

Our initial approach followed Kemppinen et al.'s glint algorithm, which converts a microfacet NDF into a spatially-varying glinty distribution using a mip hierarchy over a 2D disk parameterization of the hemisphere. The algorithm requires a UV-space Jacobian at each hit point, which in turn requires differential rays propagated through the full path. We implemented this infrastructure using Igehy 1999's equations, creating a DiffRay struct that tracks screen-space footprint differentials through transfer and reflection.

The conversion from the Shadertoy GLSL implementation to our CPU pathtracer proved harder than anticipated. Debugging revealed incorrect normal computation in the differential ray reflection function, which wasted significant time. Ultimately the full Kemppinen implementation was cut. We found that Beckmann importance sampling alone produced a visually convincing glint-like effect for many cases, though with noisier specular artifacts in complex lighting.

Snow BSDF Design — Charlie Herbert

A pure microfacet model renders snow as dark and metallic. A pure Lambertian model produces white concrete. Real snow is predominantly diffuse, with occasional sharp specular highlights from individual crystals. Our SnowBSDF::f() blends a Lambertian diffuse base with a Beckmann specular component, scaled by tunable weights. The Fresnel term uses a dielectric formulation with snow's index of refraction (1.31), reflecting the fact that individual ice crystals are optically transparent even though the bulk material scatters diffusely.

Triplanar Mapping + Seam Fix — Charlie Herbert · Allena Ogilvie

SDF-generated meshes carry no UV coordinates. Both the Kemppinen algorithm and the texture-based BSDF require UV positions and Jacobians at hit points. We solved this with triplanar mapping: projecting the world-space hit point onto three axis-aligned planes and blending results by surface normal alignment. For the triplanar equations, we adapted Martin Palko's Unity shader code to our C++ framework, adding coordinate tiling via modular rescaling.

The initial linear blend weights created hard diamond-shaped seam artifacts where two projection axes shared similar alignment. The fix was to raise each axis's weight to the 4th power before normalizing across all three. This sharpens the per-axis falloff so that one axis dominates cleanly near its aligned direction, eliminating seams without requiring additional sampling.

Ray Differentials — Charlie Herbert

The Kemppinen algorithm and triplanar Jacobian both require screen-space differentials propagated through ray bounces. We implemented this using Igehy 1999's equations, creating a DiffRay struct that extends the base Ray with four differential vectors: do_dx, dd_dx, do_dy, dd_dy, and a last_normal for triplanar weight computation. The camera generates initial differentials from the camera-to-world matrix. Each bounce calls transfer() and reflect() to propagate them through the scene, allowing the UV Jacobian to be reconstructed at any hit point as a 2x2 matrix from the differential origin offsets.

SDF Snow Accumulation — Sophia Liu · Jeffrey Fang

To simulate snow accumulation, we cast rays downward into the scene. At each hit point, we deposit a snow blob by creating an ellipsoid SDF and merging it with the existing voxel grid by taking the minimum value at each voxel. Negative SDF values indicate the interior of the snow surface; the isosurface at zero traces the snow boundary. The Surface Nets algorithm then converts this voxel grid into a triangle mesh by finding sign changes across voxel edges and creating quads between the four surrounding surface vertices.

Surface normals are computed from the SDF gradient using bilinear interpolation across the 12 voxel edges at each vertex, giving smooth normals without triangle-level discontinuities. A key tuning parameter was the decay rate of blob size with surface slope: too slow produced unrealistic overhanging snow; too fast produced disconnected chunky patches. A linear decay with the correct voxel granularity produced smooth, continuous accumulation.

Footprint SDF Carving — Allena Ogilvie

The proposed footprint carving was implemented using SDF subtraction. It is negating ellipsoid SDFs and merging with max instead of min to carve depressions into the snow surface. The geometry of the depression itself worked, having a boot and a foot shape that were distinguishable. Also, the carve depth was controllable through the Y radius of each ellipsoid component. Although sound in theory, the visual results had two main problems that made them unconvincing. The first is the coordinate system depth variation. A real footprint in the show is not a uniform flat depression. The heel sinks deepest, the arch barely touches, the ball of the foot creates a secondary ridge, and individual toes leave distinct, rounded pockets at varying depths. Our SDF carving used simple ellipsoidal unions, which produce a smooth bowl-shaped subtraction at each component of the render. There was no way to uncode the non-uniform vertical pressure profile of a real footstep without significantly more complex SDF composition. This would require a drastic amount of time to tune correctly and more communication of the development progress.

Secondly, the carving broke the snow material illusion. A render of the snow footprint is more akin to a footprint cutout in dough, not in snow. The current f() function samples a snow albedo texture via triplanar mapping, blending across three projection axes using power-of-4 weights. The depression creates a hard geometric boundary where the carved region meets the undisturbed surface. Without spatially varying the albedo sample or the specular contribution based on how compressed it is at each hit point. This would require reading each SDF value at dr_in→o during shading. As a result, the footprint reads as a geometric hole rather than a compression in the snow material. The material looks identical inside and outside the footprint, which breaks the illusion entirely. In real snow, a compression has a different crystal structure from the noncompressed surrounding area. The compressed snow is denser, icier, and reflects light differently from the fresh powdery snow. Given the time remaining and priority of getting a high-quality baseline snow accumulation render correctly, the footprint was cut from the final deliverable.

Problems Encountered

Communication and pacing were the biggest coordination challenges. Two separate implementations of the snow accumulation algorithm were developed in parallel before the team converged, costing significant time. A more granular roadmap with individually delegated intermediate deadlines would have substantially helped. On the technical side, the incorrect normal computation in reflect_from_next_dir in the differential ray implementation caused difficult-to-trace visual artifacts that delayed the glint work by over a week. Earlier visual testing would have surfaced this faster -- a noisy 16-sample render identifies most shading bugs far more efficiently than code review alone.
